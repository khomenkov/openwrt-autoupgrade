# openwrt-autoupgrade

Автообновление пакетов для OpenWrt 25.12+ (менеджер пакетов `apk`): запуск по расписанию, кнопки в LuCI, уведомления, защита от типичных сбоев.

Архитектура не важна, скрипты написаны на обычном `sh`. Разрабатывается на Cudy WR3000P и TR3000 (mediatek/filogic).

## Что умеет

- `apk update` и `apk upgrade` по расписанию (по умолчанию каждый день в 12:00 по времени роутера)
- четыре кнопки в LuCI (Система → Пользовательские команды): «Обновить пакеты», «Проверить обновления», «Статус автообновления», «Лог обновления»
- повторные попытки `apk update`, если сеть ещё не поднялась или WAN мигнул
- случайная задержка перед запуском по расписанию, чтобы тысячи роутеров не шли на зеркало в одну секунду
- запись «было → стало» для каждого пакета, история событий в файле
- копия настроек (`sysupgrade -b`) перед каждым обновлением
- проверка DNS после обновления и предупреждение, если он перестал отвечать
- уведомления в Telegram, ntfy или своим скриптом
- список пакетов, которые нужно обновлять вручную (`hold`)
- необязательный перезапуск сервисов обновлённых пакетов
- переживает обновление прошивки (`/etc/sysupgrade.conf`)

## Установка

На роутере по SSH:

```
wget -qO- https://raw.githubusercontent.com/khomenkov/openwrt-autoupgrade/main/install.sh | sh
```

Установщик кладёт скрипт в `/root/upgrade.sh`, создаёт файл настроек `/etc/config/autoupgrade`, добавляет кнопки в LuCI и задачу в cron.

Повторный запуск той же команды обновляет скрипт. Дублей в LuCI и cron не появляется, существующие настройки и расписание сохраняются.

### Параметры установщика

Задаются переменными перед `sh`:

| Переменная      | По умолчанию                    | Назначение                                                   |
| --------------- | ------------------------------- | ------------------------------------------------------------ |
| `REPO`          | `khomenkov/openwrt-autoupgrade` | репозиторий на GitHub                                        |
| `BRANCH`        | `main`                          | ветка, тег или хеш коммита                                   |
| `DEST`          | `/root/upgrade.sh`              | куда положить скрипт                                         |
| `CRON_SCHEDULE` | уже настроенное, иначе `0 12 * * *` | расписание cron                                          |
| `NO_CRON`       | не задано                       | `1` — не трогать cron                                        |
| `NO_LUCI`       | не задано                       | `1` — не трогать LuCI                                        |
| `NO_KEEP`       | не задано                       | `1` — не добавлять скрипт в `/etc/sysupgrade.conf`           |

Пример: запуск по воскресеньям в 04:30 и без LuCI:

```
wget -qO- https://raw.githubusercontent.com/khomenkov/openwrt-autoupgrade/main/install.sh | CRON_SCHEDULE="30 4 * * 0" NO_LUCI=1 sh
```

## Команды

```
/root/upgrade.sh          # обновить пакеты сейчас (то же, что run)
/root/upgrade.sh check    # показать доступные обновления, ничего не устанавливая
/root/upgrade.sh bg       # запустить обновление в фоне и сразу вернуться
/root/upgrade.sh status   # настройки, расписание, последние события
/root/upgrade.sh log      # история обновлений и системный лог
/root/upgrade.sh version  # версия скрипта
```

`cron` — служебная команда, её вызывает расписание: она учитывает `enabled`, случайную задержку и hold-список. Ручной запуск (`run`) их игнорирует.

Кнопки в LuCI вызывают `bg`, `check`, `status` и `log`: там команда выполняется без оболочки, поэтому `&`, `|` и скобки в ней не работают.

## Настройки

Файл `/etc/config/autoupgrade`. Все опции необязательны, ниже значения по умолчанию.

| Опция              | По умолчанию                  | Назначение                                                              |
| ------------------ | ----------------------------- | ----------------------------------------------------------------------- |
| `enabled`          | `1`                           | `0` — по расписанию ничего не делать (ручные запуски работают)          |
| `jitter`           | `1800`                        | случайная задержка перед запуском по расписанию, секунд; `0` — без неё  |
| `retries`          | `3`                           | сколько раз пробовать `apk update`                                      |
| `retry_delay`      | `120`                         | пауза между попытками, секунд                                           |
| `min_free_kb`      | `5120`                        | минимум свободного места в `/overlay`, КБ                               |
| `backup`           | `1`                           | делать копию настроек перед обновлением                                 |
| `backup_dir`       | `/root/autoupgrade-backup`    | куда складывать копии                                                   |
| `backup_keep`      | `3`                           | сколько последних копий хранить                                         |
| `health_host`      | `openwrt.org`                 | имя для проверки DNS после обновления; `none` — не проверять            |
| `restart_services` | `0`                           | `1` — перезапускать init-скрипты обновлённых пакетов                    |
| `reboot_pkgs`      | `libc busybox procd ubus ubusd base-files libubox` | после обновления этих пакетов в сообщении будет совет перезагрузиться |
| `history_file`     | `/root/autoupgrade.history`   | файл истории; `none` — не вести                                         |
| `notify`           | `none`                        | `none`, `telegram`, `ntfy` или `cmd`                                    |
| `notify_success`   | `1`                           | `0` — сообщать только об ошибках и предупреждениях                      |
| `hold`             | пусто                         | список пакетов для ручного обновления, см. ниже                         |

## Уведомления

Сообщение приходит при обновлении, ошибке и предупреждении. Если обновлений нет, молчим.

**Telegram**

```
uci set autoupgrade.main.notify='telegram'
uci set autoupgrade.main.telegram_token='123456:ABC...'
uci set autoupgrade.main.telegram_chat_id='123456789'
uci commit autoupgrade
```

Токен лежит только в файле настроек на роутере, в репозиторий он не попадает. `api.telegram.org` доступен не у всех провайдеров, в этом случае используйте `ntfy` или `cmd`.

**ntfy**

```
uci set autoupgrade.main.notify='ntfy'
uci set autoupgrade.main.ntfy_url='https://ntfy.sh/my-secret-topic'
uci commit autoupgrade
```

**Свой скрипт**

```
uci set autoupgrade.main.notify='cmd'
uci set autoupgrade.main.notify_cmd='/root/my-notify.sh'
uci commit autoupgrade
```

Команда получает текст сообщения последним аргументом.

## Список hold

Критичные пакеты можно обновлять только вручную. Допускаются шаблоны:

```
uci add_list autoupgrade.main.hold='libc'
uci add_list autoupgrade.main.hold='kmod-*'
uci commit autoupgrade
```

Если хотя бы один такой пакет есть среди доступных обновлений, запуск по расписанию **ничего не устанавливает** (в том числе остальные пакеты), пишет об этом в историю и один раз присылает уведомление. Посмотреть, что ждёт: `/root/upgrade.sh check`. Поставить всё: `/root/upgrade.sh run`.

## Что важно знать

- Массовое обновление пакетов в OpenWrt традиционно не приветствуется: пакеты собираются под конкретную прошивку, и обновление отдельных библиотек иногда ломает зависимые пакеты. Если роутер критичен для вас, оставьте в `hold` системные пакеты или запускайте обновление вручную.
- Откат версий через `apk` обычно невозможен, потому что в репозиториях лежат только свежие версии. Поэтому скрипт делает копию настроек, пишет «было → стало» и проверяет DNS, но не умеет откатывать пакеты.
- Системный лог OpenWrt живёт в RAM и пропадает после перезагрузки. Поэтому события об обновлениях и ошибках дополнительно пишутся в `history_file` (в файл пишется только то, что произошло, пустые проверки туда не попадают). Файл обрезается до последних 100 строк.
- Пока идёт случайная задержка, замок уже занят: параллельный запуск (в том числе кнопка в LuCI) сообщит, что обновление выполняется.
- Скрипт пропускает запуск, если в `/overlay` меньше `min_free_kb` свободного места.

## Безопасность

Команда `wget ... | sh` выполняет код из интернета с правами root. Чтобы защититься от случайных изменений, ставьте с конкретного тега или коммита:

```
wget -qO- https://raw.githubusercontent.com/khomenkov/openwrt-autoupgrade/<тег-или-коммит>/install.sh | BRANCH=<тег-или-коммит> sh
```

Установщик проверяет, что скачанный `upgrade.sh` начинается с `#!/bin/sh` и проходит `sh -n`, иначе рабочий скрипт не заменяется.

## Удаление

```
wget -qO- https://raw.githubusercontent.com/khomenkov/openwrt-autoupgrade/main/uninstall.sh | sh
```

Убирает cron, кнопки LuCI, строку в `sysupgrade.conf` и сам скрипт. Настройки, история и копии конфигурации остаются; чтобы удалить и их, добавьте `PURGE=1` перед `sh`. Пакет `luci-app-commands` не удаляется.

## Требования

- OpenWrt 25.12+ с `apk`
- HTTPS в `wget` (в стандартной сборке есть через `uclient-fetch` и `ca-bundle`)
- для кнопок в LuCI нужен `luci-app-commands` (установщик ставит его сам, если LuCI есть)

## Разработка

Тесты проверяют логику на заглушках `apk`, `uci`, `logger` и других команд, настоящий роутер не нужен:

```
sh tests/run.sh
```

В GitHub Actions на каждый коммит запускаются ShellCheck, проверка синтаксиса BusyBox ash и эти тесты. Тесты не заменяют проверку на устройстве: формат вывода `apk list` и `apk info -L` они берут из заглушек.
